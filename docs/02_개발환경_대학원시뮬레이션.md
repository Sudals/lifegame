> 작성일: 2026-11-04 · 목표: 웹(Vercel) 우선 배포, 동일 코드로 Electron exe 확장

## 1. 아키텍처 핵심 결정

> **Vercel에는 Electron 앱이 아니라 "웹 빌드"가 올라갑니다.**
> 따라서 게임 본체는 **순수 웹앱(Vite + React + TS)** 으로 만들고, Electron은 그 빌드를 감싸는 **얇은 셸**로만 둡니다.
> → 하나의 코드베이스로 웹/데스크톱 동시 대응.

```
┌──────────────────────────── monorepo ────────────────────────────┐
│ apps/web        Vite + React 게임 본체  ──build──▶ Vercel(정적)   │
│ apps/desktop    Electron 셸 (web 빌드 로드) ──build──▶ .exe       │
│ api/            Vercel Functions (세이브/랭킹)  ──▶ Postgres(DB)  │
│ packages/engine 게임 로직(순수 TS, UI 무관, 테스트 대상)           │
│ packages/content 연구실·주제카드·학회·이벤트 JSON + 스키마          │
└──────────────────────────────────────────────────────────────────┘
```

**원칙**
1. **게임 로직(engine)은 UI·플랫폼과 분리** — 순수 함수 + 시드 RNG. 테스트·밸런싱 시뮬레이션 가능.
2. **콘텐츠는 데이터** — 전공 추가 = JSON 데이터팩 추가.
3. **오프라인 우선** — 세이브는 로컬이 기본, 서버는 클라우드 세이브/랭킹용 옵션.
4. **플랫폼 추상화** — `SaveStorage` 인터페이스로 웹(IndexedDB) / Electron(파일) 구현 분리.

## 3. DB 선택 — Neon vs 대안

### 3.1 먼저: DB가 꼭 필요한가?
- **싱글플레이 진행 자체는 DB 불필요** (로컬 세이브로 충분).
- DB가 필요한 기능: 클라우드 세이브, 랭킹(최종 스코어), 통계 수집(어떤 연구실을 많이 고르나 등), 계정.
- → **v0.1은 로컬 세이브만**, v0.2에서 DB 연결해도 늦지 않음. 단 스키마는 미리 설계.

### 3.2 후보 비교 (무료 티어 기준, 세부 한도는 수시 변경되므로 가입 전 공식 가격 페이지 확인)

| 항목 | **Neon** (Postgres) | **Supabase** (Postgres) | **Turso** (libSQL/SQLite) |
|---|---|---|---|
| Vercel 연동 | ◎ Vercel Marketplace 공식 통합, 환경변수 자동 | ○ 통합 있음 | ○ 통합 있음 |
| 무료 티어 특징 | 유휴 시 scale-to-zero → **콜드스타트 수백 ms** 발생 | 일정 기간 미사용 시 **프로젝트 일시정지** (수동 재개 필요) | 넉넉한 무료 읽기/쓰기, 엣지 복제 |
| 속도 | 서버리스 드라이버(HTTP) 빠름, 콜드스타트만 주의 | 상시 가동 중엔 안정적 | 읽기 지연 매우 낮음 |
| 부가 기능 | 브랜치(개발 DB 분리) 우수 | **Auth, Storage, Realtime 올인원** | 임베디드 레플리카(로컬 SQLite 동기화) |
| Electron 궁합 | 서버 경유 | 서버 경유 | ◎ 로컬 SQLite와 같은 방언 → 오프라인 세이브 동기화에 유리 |
| 안정성/생태계 | Postgres 표준, 이전 쉬움 | Postgres 표준, 커뮤니티 최대 | SQLite 기반, Postgres 대비 기능 제한 |

### 3.3 추천
- **기본 추천: Neon 유지 (OK 선택입니다)**
  - 이 게임의 서버 트래픽은 "세이브 업로드·랭킹 조회" 정도라 콜드스타트 수백 ms는 체감이 거의 없음.
  - 무료 티어에서 **프로젝트가 정지되지 않는다**는 점이 Supabase 대비 장점 → 방치형 개인 프로젝트에 안정적.
  - Vercel 공식 통합으로 세팅이 가장 간단.
- **Supabase가 더 나은 경우**: 로그인(구글/카카오 소셜 로그인)·랭킹을 빨리 붙이고 싶을 때. 인증을 직접 안 만들어도 됨. 단 장기 미접속 시 일시정지 주의(무료).
- **Turso가 더 나은 경우**: Electron exe에서 **오프라인 플레이 + 나중에 동기화**를 핵심 기능으로 할 때.

> ✅ **확정 (2026-11-04): Neon + Drizzle.** 인증은 v0.1 익명 UUID, 필요 시 Auth.js(Neon에 세션 저장)로 확장. Drizzle을 쓰면 나중에 다른 Postgres로 이전도 쉬움.

### 3.3.1 데이터 배치 원칙 (확정)

| 데이터 | 위치 | 이유 |
|---|---|---|
| 게임 콘텐츠 (선택지·대사·연구실·주제카드·학회·저널·이벤트·밸런스) | `packages/content/*.json` (빌드에 포함) | exe 오프라인 플레이, 지연 0, 코드와 동일 버전 관리, 랭킹 재계산 검증 |
| 플레이어 데이터 (세이브·엔딩 기록·랭킹·통계) | **Neon** | 기기 간 동기화, 공유 랭킹 |
| 로컬 세이브 | IndexedDB(웹) / userData 파일(Electron) | 오프라인 기본, 클라우드 세이브는 선택 |

- 추후 라이브 운영·비개발자 편집이 필요해지면 **하이브리드**로 전환: Neon에 `content_drafts` 테이블 + 관리자 화면 → 빌드 시 JSON으로 export → 게임은 계속 JSON을 읽음.

### 3.4 초기 스키마 (Drizzle, Postgres)

```ts
// api/db/schema.ts
import { pgTable, uuid, text, integer, jsonb, timestamp } from 'drizzle-orm/pg-core';

export const players = pgTable('players', {
  id: uuid('id').primaryKey().defaultRandom(),
  nickname: text('nickname').notNull(),
  createdAt: timestamp('created_at').defaultNow(),
});

export const saves = pgTable('saves', {
  id: uuid('id').primaryKey().defaultRandom(),
  playerId: uuid('player_id').references(() => players.id).notNull(),
  slot: integer('slot').notNull(),           // 1~3
  gameVersion: text('game_version').notNull(), // 세이브 마이그레이션용
  data: jsonb('data').notNull(),              // 직렬화된 GameState
  updatedAt: timestamp('updated_at').defaultNow(),
});

export const runs = pgTable('runs', {          // 엔딩 기록 = 랭킹
  id: uuid('id').primaryKey().defaultRandom(),
  playerId: uuid('player_id').references(() => players.id),
  major: text('major').notNull(),            // 'ai'
  labId: text('lab_id').notNull(),
  career: text('career').notNull(),
  score: integer('score').notNull(),
  papers: jsonb('papers').notNull(),         // [{venue, tier, authorOrder}]
  seed: text('seed').notNull(),              // 검증/재현용
  finishedAt: timestamp('finished_at').defaultNow(),
});
```
- 랭킹 치팅 방지(추후): 서버에서 `seed + 선택 로그`로 engine 재실행해 점수 검증 → engine이 순수 TS라 가능.

```bash
pnpm create electron-vite apps/desktop   # 또는 수동 구성
pnpm --filter desktop add -D electron electron-builder
```

## 6. 배포

### 6.1 웹 (Vercel)
1. GitHub 저장소 연결 → Vercel 프로젝트 생성
2. Root: 레포 루트, Build: `pnpm --filter web build`, Output: `apps/web/dist`
3. `api/` 폴더는 자동으로 Serverless Functions 배포
4. 브랜치별 Preview 배포 → 플레이테스트 링크 공유
5. Neon 브랜치 기능으로 Preview용 DB 분리(선택)

```json
// vercel.json
{
  "buildCommand": "pnpm --filter web build",
  "outputDirectory": "apps/web/dist",
  "rewrites": [{ "source": "/((?!api/).*)", "destination": "/index.html" }]
}
```

### 6.2 데스크톱 (Electron exe)
- `apps/desktop`이 `apps/web/dist`를 로드 (프로덕션: `loadFile`, 개발: Vite dev 서버 URL).
- 세이브: `preload.ts`에서 `window.platform.save/load` 노출 → `app.getPath('userData')`에 JSON 저장.
- 보안: `contextIsolation: true`, `nodeIntegration: false`, 외부 URL 로드 금지.
- 빌드: `electron-builder --win nsis portable` → 설치형 + 포터블 exe.
- 코드 서명: 미서명 시 SmartScreen 경고 → 정식 배포 시 인증서 검토.
- Steam 출시 고려 시: Steamworks(greenworks/steamworks.js) 연동, 업적 = 게임 내 업적 매핑.

### 6.3 플랫폼 추상화 예시
```ts
// apps/web/src/platform/SaveStorage.ts
export interface SaveStorage {
  save(slot: number, data: string): Promise<void>;
  load(slot: number): Promise<string | null>;
  list(): Promise<{ slot: number; updatedAt: string }[]>;
}
// web → IndexedDB 구현 / electron → window.platform(IPC) 구현
export const storage: SaveStorage =
  'platform' in window ? electronStorage : indexedDbStorage;
```

## 7. 그래픽(HD 도트) 파이프라인

| 항목 | 규칙 |
|---|---|
| 내부 해상도 | 640×360 기준 (16:9), 정수배 스케일(×2=720p, ×3=1080p, ×4=1440p) |
| 렌더 | `image-rendering: pixelated;` 서브픽셀 이동 금지(좌표 정수 반올림) |
| 캐릭터 | 반신 128px 높이, 표정 레이어 분리(몸/얼굴/이펙트) |
| 배경 | 640×360 1장, 시간대 변형(낮/밤/새벽)은 팔레트 스왑 or 오버레이 |
| 팔레트 | 고정 팔레트 파일(`palette.hex`)로 전 에셋 통일 |
| 포맷 | PNG(무손실), 스프라이트시트 + JSON(Aseprite export) |
| 폰트 | 한글 도트 폰트(상업 이용 가능 라이선스 확인, 예: Galmuri 계열 OFL) |
| 라이선스 | 외부 에셋은 `docs/ASSETS_LICENSE.md`에 출처·라이선스·상업 가능 여부 기록 |

**Claude Code로 에셋 제작 시 흐름**
1. Claude Code가 픽셀 배열(JSON/SVG `rect`)로 스프라이트 생성 → 스크립트로 PNG 변환(sharp / node-canvas)
2. 팔레트 강제 스크립트로 색 정규화
3. Aseprite에서 사람이 보정(외곽선·명암)
4. `assets/` 커밋 → 빌드 시 아틀라스 패킹(선택: `free-tex-packer`)

## 8. Claude Code 작업 규칙 (CLAUDE.md 초안)

```md
# CLAUDE.md
- 게임 로직은 packages/engine에만 작성. React/DOM import 금지.
- 모든 랜덤은 engine/rng.ts의 시드 RNG 사용 (Math.random 금지).
- 콘텐츠(연구실/주제/학회/이벤트)는 packages/content JSON에 추가하고 zod 스키마 통과 필수.
- 밸런스 수치 하드코딩 금지 → content/balance.json.
- 새 기능은 vitest 테스트 동반. `pnpm test` 통과 후 커밋.
- 도트 에셋: 640x360 기준, palette.hex 외 색상 금지.
- 세이브 포맷 변경 시 gameVersion 올리고 migrate 함수 추가.
```

## 9. 품질 관리

| 항목 | 방법 |
|---|---|
| 단위 테스트 | engine 함수(스탯 변화, 심사 판정, 달력) |
| 밸런스 시뮬 | 봇 전략(성실형/밤샘형/워라밸형) × 1만 회 자동 플레이 → 졸업률·평균 점수·논문 분포 리포트 |
| 콘텐츠 검증 | CI에서 zod 스키마 + 참조 무결성(존재하지 않는 eventId 등) 검사 |
| E2E | Playwright: 새 게임 → 컨택 → 1학기 진행 → 세이브/로드 |
| CI | GitHub Actions: lint → test → build (Vercel은 자체 빌드) |
| 에러 수집 | (선택) Sentry 무료 티어 |
